# LM14 — Pólya's Problem Solving
*Deep dive + project ([[DR-009 - Learning Method Deep Dives|DR-009]]). Hub: [[LM00 - Learning Methods Hub|Learning Methods]] · Method in practice: [[how-i-study]] §1*

> [!NOTE] Evidence: **Classic framework; works with practice and self-monitoring**

## In plain words
Four steps:
1. Understand the problem.
2. Devise a plan (look for a related problem, work backwards, solve a simpler case).
3. Carry it out.
4. Look back: check the answer and ask what you can reuse.

## The evidence, honestly
Pólya, *How to Solve It* (1945), is a classic of advice, not an experiment.
Schoenfeld (1985) found students rarely benefit from a list of heuristics alone. They improve when they practise choosing a heuristic and monitoring their progress ("is this working?").
So use the four steps out loud, with check-ins.

## Using it in EECS
- "Solve a simpler case" is recursion and base cases.
- "Work backwards" is loop invariants and proofs.
- "Look back" is the post-mortem after a bug.

## Common mistakes
- Skipping step 1: coding before you can restate the problem.
- Skipping step 4, where the reusable insight is.

## 🔨 Project: Puzzle set with labeled steps
5 Human Resource Machine levels or 5 Project Euler problems, each with the four steps written out. Add a "look back" insight you reuse on a later problem.
- **Done when:** 5 write-ups exist, and at least one "look back" insight was reused on a later problem.
- **Level:** Beginner.
- **Fits with:** The four Pólya steps written out in the math stages' word problems (M02–M11).

## Sources
- Pólya, *How to Solve It* (1945).
- Schoenfeld, *Mathematical Problem Solving* (1985).
